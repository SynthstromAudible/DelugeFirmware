- [] FLOAT->Q31 conversion (`convert_range_simd` in src/deluge/storage/audio/stream/convert.h) is SIMD (`Argon<float>::ConvertTo<int32_t, 31>()`, i.e. `vcvtq_n_s32_f32`) only when compiling for real NEON/MVE (`__ARM_NEON` / `__ARM_FEATURE_MVE` -- the arm-none firmware, qemu-arm, Apple Silicon), gated by `#if` in `convert_range_simd`. On x86-SIMDe hosts (where the goldens render) it stays on the scalar `q31_from_float` path, because SIMDe's software emulation of `vcvtq_n_s32_f32` diverges from the scalar reference: input `1.0f` (exact saturation boundary) produced `0x80000000` instead of the saturated `0x7FFFFFFF`, and `NaN` produced `0x00000000` instead of saturating to `0x7FFFFFFF` (see convert_cluster_spec.cpp's FLOAT case, Phase 2d Task 4). - [] the Rust BSP has NO non-probe debug transport: `deluge_log` (src/bsp/rust/src/services.rs:133) writes to `rtt_target::rprint!` only under the `rtt` cargo feature, and drops the string otherwise — without a debug probe attached the device is silent. The legacy RZA1 BSP had a fallback that exfiltrated debug text over the **MIDI DIN UART** (`bufferMIDIUart`, the `#else` of `HAVE_RTT` in src/bsp/rza1/drivers/uart/uart.c), corrupting the MIDI stream in exchange for output; that path retires with the legacy BSP. Two viable routes with opposite failure modes: (a) **blocking/polled TX on a spare SCIF channel** — rza1l-hal/src/uart.rs already drives all five SCIF channels and only SCIF0 (MIDI) and SCIF1 (PIC) are claimed, so SCIF2/3/4 are free at a real baud rate rather than 31250; works inside fault handlers, before the scheduler exists, and with interrupts off; gated on whether those pins are physically broken out on the PCB. (b) **USB-CDC** — embassy-usb 0.6 ships `class/cdc_acm.rs`, and src/bsp/rust/src/usb.rs already builds an embassy-usb device with the MIDI class (`EMBASSY_USB_MAX_INTERFACE_COUNT=8` leaves room); needs no probe or extra cable and has real throughput, but is dead during panics, hangs, early boot, and whenever USB itself is the broken thing. Likely end state is both, layered behind one `deluge_log` sink that routes by context. Note separately that any transport also needs `ENABLE_TEXT_OUTPUT`, defined for Debug/RelWithDebInfo only (src/deluge/CMakeLists.txt:61) — a Release image is silent regardless of transport.
