# `menu-hierarchies.json`

Generated by `deluge_menu_dump` (`src/scenes/menu/menu_dump_main.cpp`) from the declarative menu
tree (`src/scenes/menu/nodes/`). Never edit this file by hand -- `scripts/menu_dump_check.sh`
regenerates it and fails CI if the regenerated content differs from what is committed here.

Read `menu_dump_main.cpp`'s own file header for the full schema (it recovers and documents the
retired Python `DocEmitter`'s shape, then explains exactly how and why this dump's shape differs
from it). Two differences matter enough to repeat here, for anyone consuming this JSON rather than
just diffing it:

- **`"description"` is never present**, on any entry -- not even as `""`. `Node` (the type this
  tree is built from) carries no such data, so there was nothing to put there. Code written
  against the old schema's assumption that every entry has a `description` key will fail on this
  file's actual shape.
- **A `"multicontext"`-typed entry (a node with `dynamic_children` set) does not exist in this
  file today, and if one ever does, it means the dump tool has stopped and refused to run**
  rather than guess a JSON shape for it: `deluge_menu_dump` exits non-zero and prints the
  offending node to stderr instead of emitting anything. As of this writing no node in the tree
  uses `dynamic_children`, so this is a design gap flagged in code rather than something this file
  has ever actually contained. Do not assume a `"multicontext"` entry here means what the retired
  `doc_emitter.py`'s `"multicontext"` type meant -- that Python type had no `"children"` key at
  all; this dump has no verified equivalent yet.
