# Level 3 (spec G §4.2): **the branch's acceptance test.** One script, run twice against two SD-card
# fixtures that differ by exactly one file, and the two trees compared against each other:
#
#   ui_app_scripts_menu        SD root tests/fixtures/card             -> ShellMenu OFF: legacy SoundEditor
#   ui_app_scripts_menu_shell  SD root tests/fixtures/card-shell-menu  -> ShellMenu ON:  ported MenuScene
#   ui_app_scripts_menu_ab     scripts/ui_app_ab_check.py over the two got trees
#
# There is no env var and no new script verb for the toggle, and that is deliberate.
# `shellMenuEnabled()` reads `runtimeFeatureSettings.get(RuntimeFeatureSettingType::ShellMenu)`
# (`gui/ui/shell_menu_entry.cpp:103-105`); the setting is registered with xmlName "shellMenu" and
# default Off (`model/settings/runtime_feature_settings.cpp:175-178`) and read from
# `SETTINGS/CommunityFeatures.XML` on the card (`RuntimeFeatureSettings::readSettingsFromFile`,
# `:194-222`). So the toggle-on leg is a genuine boot-from-settings on the mechanism the device
# itself uses, not a test-only door.
#
# **Neither leg mutates its own input**, which matters because a test that edits its input is not
# reproducible. With the file present `bootstrap_action` returns `Bootstrap::Load`
# (`storage/existence_policy.cpp:12-24`) and the `WriteDefaults` arm that would `mkdir`/`rename`
# (`runtime_feature_settings.cpp:200-217`) is never entered; the OFF leg does enter it, but its
# `mkdir` finds `SETTINGS/` already there and its `rename` of a root-level "CommunityFeatures.XML"
# that does not exist fails, so it returns having created nothing (`:204-216`). Checked rather than
# reasoned: `git status --short tests/fixtures/` is empty after both legs have run.
#
# **What this script presses, and why it presses exactly this.**
#
# Boot lands in `InstrumentClipView`, not the session view -- `boot.state` shows `led Clip on`
# and `led Synth on`, and a `SoundEditor::setup` breakpoint on the SELECT press below stops with
# `InstrumentClipMinder::buttonAction` one frame up (`model/clip/instrument_clip_minder.cpp:392-424`:
# the gate at `:399`, the guest arm at `:408-411`, legacy's at `:415-424`). That is **site 6** of the
# fourteen in `gui/ui/shell_menu_entry.cpp`'s table, the site whose root is `soundEditorRootMenu` /
# `MenuContext::Root::Sound`.
#
# **The four null-clip sites cannot be scripted here, and it is not the port's fault.**
# `sound_editor.cpp:1893`'s `else if (clip->type == ClipType::AUDIO)` runs whenever `currentSound`
# is null, and `newSound` is only ever assigned inside `setup()`'s `else if (clip)` arm
# (`:1679-1744`) -- so a `setup()` with a null clip dereferences null. **Measured** for site 1
# (`gui/views/view.cpp:477`, SHIFT+SELECT) and site 2 (`gui/views/session_view.cpp:569`, SELECT from
# the session view): both SIGSEGV at that line under gdb, in the TOGGLE-OFF leg, on an unmodified
# tree. Sites 3 (`gui/views/arranger_view.cpp:346`) and 4 (`gui/views/performance_view.cpp:898`)
# pass the same null clip into the same function and so reach the same line, but were not driven --
# that is inspection, not a measurement. Pre-existing, and latent rather than fatal on the device,
# where address 0 is mapped. Recorded in F1 task 11's report; this script stays on a clip-carrying
# site so that the leg it would crash is the one that has to run.
#
# The shape is spec E §7's: boot into a scene, one navigation, one edit gesture, one popup, back out.
#
# 50 ms rather than 0: the legacy app blits its first OLED frame from inside the main loop, after
# its first input poll, so nothing has been drawn at 0 ms (boot.txt's own note).

# F2 task 8: **one MenuAction verb, performed end to end, from a real press.**
#
# Everything above is the *shape* of a menu visit. Everything below drives
# `MenuAction::SetClipLengthToSampleLength` through `gui::ui::dispatchShellActions`'s arm
# (`gui/ui/shell_action_dispatch.cpp`) and photographs the popup it raises -- and the toggle-OFF
# leg performs the same verb through `audio_clip::SetClipLengthEqualToSampleLength::selectButtonPress`
# (`gui/menu_item/audio_clip/set_clip_length_equal_to_sample_length.h:26-29`). The two popups are
# byte-identical, which is the claim.
#
# **Why this verb, when the plan asked for a different one.** Of `MenuAction`'s seven enumerators,
# six cannot be reached by any script, and five of those for one reason: `SoundEditor::setup`
# dereferences a null `clip` at `gui/ui/sound_editor.cpp:1893` (`else if (clip->type == ...)`,
# reached whenever `currentSound` is null), so every `soundEditor.setup()` call that passes no clip
# SIGSEGVs the OFF leg on the host sim. That is sites 1 (SHIFT+SELECT -> Settings), 2 and 3
# (SELECT from the session view / arranger -> Song) and 4 (performance view), i.e. every root that
# holds `SetShortcutsVersion`, `ScreensaverSettingsChanged`, `OpenSongMidiLearn`, `OpenSongMacros`
# and `OpenPerformanceView`. Measured under gdb, in the toggle-OFF leg, on an unmodified tree --
# the same pre-existing legacy bug F1 task 11 recorded in this file's own note above, which is why
# the script had stayed on `InstrumentClipMinder`'s clip-carrying site 6. `StartStemExport` is
# reachable only from the song root (the same crash) or the kit-global-FX root, which needs a kit
# this empty card cannot create ("NO MORE PRESETS FOUND"), and would write stems to the fixture.
# That leaves this one. F2 task 8's report has the whole table.
#
# **The route is the gesture a user performs**, not a back door: convert the boot song's one
# (empty) synth clip to an audio clip in the song view -- hold its pad, press the select encoder
# (`gui/views/session_view.cpp:525-540`, `replaceInstrumentClipWithAudioClip` at `:539`) -- enter
# it, open its menu (site 5, `gui/views/audio_clip_view.cpp:423-426`), and walk ACTIONS -> SET CLIP
# LENGTH.
#
# **The timings below are not padding, and three of them are load-bearing.**
#
#   * **1700 -> 2900 before the first pad.** `SessionView::padAction`'s clip arm is gated on
#     `currentUIMode == UI_MODE_NONE` (`session_view.cpp:739`), and the clip-view -> song-view
#     transition holds `UI_MODE_ANIMATION_FADE` (44, `gui/ui/ui.h:60`) for about a second. A pad
#     pressed inside that window is swallowed silently -- measured: `currentUIMode == 44` at a
#     `padAction` breakpoint 400 ms after the SESSION press.
#   * **pad 0 7, not pad 0 0.** `songViewYScroll` is -7 on a fresh song, so
#     `getClipOnScreen(yDisplay)` is `sessionClips[yDisplay - 7]`: row 7 is the song's one clip and
#     row 0 is nothing. Pressing row 0 falls into the *create* arm instead, and the SELECT that
#     follows then reaches `session_view.cpp:569`'s no-clip `soundEditor.setup()` -- site 2, i.e.
#     the crash above.
#   * **6000 -> 6350, the whole tail.** `SET CLIP LENGTH EQUAL TO SAMPLE LENGTH` is wider than the
#     panel, so the selected row's label side-scrolls, and the two legs scroll it with different
#     code: legacy registers `OLED::setupSideScroller` (`gui/menu_item/submenu.cpp:123-124`) and
#     the port animates `ui::oled::scroll_text` inside `list` (`ui/oled/list.h`). **They stay in
#     step for the first ~400 ms and drift apart after it** -- measured at 50 ms granularity: the
#     two legs are byte-identical at 100/250/300/350/400 ms past the turn and differ at 500 ms and
#     beyond. So the press and its snapshot both happen inside that window. This is a real
#     divergence and it is recorded rather than dodged: it is the same
#     `setupSideScroller`-has-no-port gap `scenes/menu/nodes/output_items.h` already lists, seen
#     here on a menu row instead of an output name.
1700   button Session down
1720   button Session up
2900   snapshot song-view
