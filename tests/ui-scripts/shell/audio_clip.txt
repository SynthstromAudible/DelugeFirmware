# Level-2 acceptance (E4 task 13): `audio_clip::AudioClipScene` (E4 tasks 11-12), the first ROOT
# scene in the registry -- and the first script anywhere on this stack to run with the three REAL
# shell services (`services::ModKnobs`, `GlobalControls`, `MidiLearn`) rather than `Services{}`.
#
# **How the scene gets on the stack:** `RunOptions::initial_scene`. It is a root
# (`AudioClipScene::is_root()`), and a root is exactly what a shell is booted onto; the fixture
# calls `audio_clip_scene().open(clip, song)` first, which is the order `AudioClipView::focusRegained`
# has too.
#
# **Why the fixture's zoom and length are 48 and 768, and why that is not decoration.**
# `find_peaks_per_col` only takes its cached whole-cluster arm when a display column spans two or
# more clusters (`model/sample/waveform_scan.cpp:220-230`); on any other arm it opens a
# `SampleFrameReader`, which fails with no card and makes the whole scan return false -- and then
# BOTH the pads and the OLED go black and a golden records nothing. `audio_clip_scene_spec.cpp`'s
# `Sentinel` docstring carries the arithmetic; the pair used here is its own (48 ticks per column,
# 768 ticks of clip = 32768 frames = two clusters per column). Every edit below preserves it: the
# length edit takes 768 -> 288 and the sample's end with it (196608 frames), which is 32768 frames
# per column again, and the scroll moves by exactly one column.
#
# **The real services are visible in every `.state` here**, and only here: the `led` lines for
# PLAY/RECORD/TAP TEMPO/SYNC SCALING/SAVE/LOAD/CLIP are `GlobalControls::leds`
# (`services/global_controls.cpp:600-620`) and the `indicator` lines are `ModKnobs::leds`. A run
# with `Services{}` -- which is every other script in this directory -- has neither.
0     snapshot idle              # the audio clip view: the output name on the OLED, the waveform on
                                 # the pads, and the service LEDs/indicators in `.state`
# `end_square` is `(loopLength - xScroll - 1) / xZoom` = (768 - 0 - 1) / 48 = 15
# (`audio_clip_scene.cpp:502-505`, legacy's `audio_clip_view.cpp:502-507`).
100   pad 15 3 down 64
120   pad 15 3 up
200   snapshot end_marker        # `:548-555`: the end column, tapped with no marker up, raises the
                                 # blinking end marker
300   pad 5 3 down 64
320   pad 5 3 up
400   snapshot after_length_edit # `:518-525`: with the end marker up, any other column becomes the
                                 # new length -- (5 + 1) * 48 = 288 ticks, and the underlying
                                 # sample's end moves with it (524288 frames -> 196608, which is
                                 # still 32768 frames per column, so the scan still hits its cache).
                                 # The clip is six columns wide now: the waveform is the first third
                                 # of the sample, drawn small because `cluster_peak` grows with the
                                 # cluster index, and the greyed "past the end" region fills the
                                 # rest. The end marker is in its blink-off phase in this frame --
                                 # `scroll_popup` below catches it lit
500   encoder Horizontal +1
600   snapshot scroll_popup      # **A scroll that MOVES NOTHING, and still pops up.** After the edit
                                 # above the clip is 288 ticks -- six columns at this zoom -- so it
                                 # is shorter than the sixteen-column screen and
                                 # `TimelineState::scroll` refuses to move (`max_length()` is the
                                 # gate). `displayScrollPos()` fires anyway, because legacy's call
                                 # sits OUTSIDE the `if (newXScroll != ...)` guard
                                 # (`clip_navigation_timeline_view.cpp:221`; the port transcribes the
                                 # placement and says why at `audio_clip_scene.cpp:743-750`). So the
                                 # pads are `after_length_edit`'s and the popup reads "1 : 1 : 1" --
                                 # bar 1, beat 1, tick 1, i.e. still at the top. Nothing else in the
                                 # tree pins that placement, and getting it wrong would silently
                                 # delete a popup the device shows.
700   button XEnc down
750   button Back down
770   button Back up
850   snapshot after_clear       # `audio_clip_view.cpp:417-447`: BACK while the horizontal encoder
                                 # is held clears the clip -- the sample is detached, so the pads go
                                 # dark -- and files the CLEARED popup
# Snapshotted BEFORE the X-encoder is released, deliberately: the release arm takes the popup down
# again (`audio_clip_view.cpp:85-87`'s `display->cancelPopup()`, ported as a `CancelPopup` notice),
# so a frame taken after it records the clear with no popup and says nothing about the popup at all.
# Written the other way round first, and the golden is what showed it.
900   button XEnc up
1000  quit
