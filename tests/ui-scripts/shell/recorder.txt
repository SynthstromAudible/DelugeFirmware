# Level-2 acceptance: `recorder::RecorderScene`, entered through **both**
# of its doors in one run.
#
# **The ordinary door first.** `nodes::sample0_recorder` is a child of `nodes::sound_actions`
# (`nodes/sound_actions.h`) and of `nodes::drum_actions` (`nodes/roots.h`), both
# `Layout::Vertical` -- and `ui::oled::list` sets `entered` for any selectable row
# (`ui/oled/list.cpp`) while `render_vertical` marks every row selectable. So SOUND -> ACTIONS ->
# RECORD TO SAMPLE is two ordinary select presses, and that is how a user reaches it.
#
# **Then the shortcut door**, (0,4) of `kSoundCells` (`menu/shortcuts.cpp`, legacy's own
# `paramShortcutsForSounds` cell). `setup()` lands on the chain page that lists the item -- the SAMPLE RECORDER page,
# focused on it -- exactly as the ordinary door's second select did, and opens nothing; a select there opens the
# recorder. `after_shortcut` is the page, `after_shortcut_open` the recorder over it.
#
# Both doors open the recorder from the SAMPLE RECORDER page, so both closes land as
# `osc::AudioRecorder::beginSession` lands them: on the source page, at the root, with the file selector focused.
#
# **The recorder here is real.** `on_enter` allocates a genuine `SampleRecorder` through
# `AudioEngine::getNewRecorder` and publishes it with `AudioEngine::setForegroundRecording`, exactly
# as on the device; nothing is stubbed. What a spec process has no way to do is *capture* into it --
# nothing pumps the audio thread -- so `numSamplesCaptured` stays 0. That is what shapes both closes:
# BACK -> `endRecordingSoon` (`audio_recorder.cpp`) -> `SampleRecorder::endSyncedRecording`,
# whose `numSamplesCaptured == 0` arm **aborts** (`model/sample/sample_recorder.cpp:1258-1261`);
# `after_render`'s completion arm then sees `status >= COMPLETE`, attaches nothing (the `ABORTED`
# guard), runs `finish_recording()` and files the `Remove` that closes the scene.
#
# `idle` is also where the LEDs and the greyout are recorded: `opened()`'s LED tail (`:100-106`) is
# BACK at the 110 ms blink, RECORD at the 60 ms one, and SYNTH lit because the context is not a kit;
# and there are **no pad lines at all**, because `getGreyoutColsAndRows`' `*cols = 0xFFFFFFFF`
# (`:58-61`) takes the menu's own shortcut flash underneath all the way to black. The greyout is
# legible here as an absence.
#
# There is deliberately NO quiet-tick frame while the recorder is up. `next_timer()` does fire every
# 10 ms -- it is what replaces legacy's `while (true)` -- but a poll that finds nothing draws the
# same panel, the same LEDs and the same (empty) pad set, so the golden would repeat its predecessor.
# The poll is covered instead by `recorder_scene_spec.cpp`, which can move `numSamplesCaptured`
# under it.
