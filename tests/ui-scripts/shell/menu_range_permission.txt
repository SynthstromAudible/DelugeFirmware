# Level-2 acceptance: a range-dependent leaf (nodes::source0_transpose) reached as
# row 1 of a small vertical wrapper, with two MultiRanges on the source.
#
# Entry is not *refused*: `Permission::MustSelectRange` makes `MenuScene::enter_child` open `nodes::multi_range` in the leaf's place -- legacy's own
# `multiRangeMenu.menuItemHeadingTo = newItem; newItem = &multiRangeMenu;` (`sound_editor.cpp:1857-1858`).
# So `after_select_press` is the real range picker, listing both ranges by name, and `after_back`
# is the wrapper again. The script pins that the *leaf* is never opened and its value never
# moves.
0     snapshot idle
100   encoder Select +1
120   snapshot after_select_turn
200   button SelectEnc down
220   button SelectEnc up
240   snapshot after_select_press
300   encoder GoldUpper +2
# the GoldUpper turn above lands on the page the select press opened, which reads no
# edit encoder -- so it inks nothing new and a snapshot would be byte-identical to `after_select_press`.
# The step stays (the spec asserts the value did NOT move here) and there is no snapshot: a golden
# that records nothing is a golden that can never fail for the right reason.
400   button Back down
420   button Back up
440   snapshot after_back
500   quit
