# Level-2 acceptance: `overlay::ParamPopupScene`, pushed by `services::ModKnobs`.
#
# **How the scene gets on the stack: nothing in this script pushes it.** A gold-knob turn is offered
# to the top scene first (`shell/router.h`'s `route()`, which is legacy's `UI::modEncoderAction` ->
# `view` fallback), `AudioClipScene` declines it explicitly ("the two gold knobs and the tempo
# encoder are `services::ModKnobs`'s", `audio_clip_scene.cpp`), and
# `ModKnobs::turn_knob` then writes the param and calls `show_popup`, whose presentation runs
# `stack_.push(SceneId{kParamPopupSceneKind})` (`GuestKnobPresentation::show_value_popup`). **This script
# cannot exist with `Services{}`**: with a null mod-knob service the turn is dropped and no popup
# frame is ever produced. It is the one script here whose whole subject is a service.
#
# The base scene is `AudioClipScene` on the same clip the knobs are pointed at, so the popup is
# composited over something rather than over a blank panel -- `ParamPopupScene::oled_transparent`
# reports true for `SurfaceRole::Main` precisely so the scene beneath shows around it.
#
# Every gold turn acts, as `main`'s `interpretEncoders` does: one detent writes the param and pushes the popup.
#
# **`popup_moved` guards the repaint:** a second detent on an already-open popup moves the scene's text, and with
# nothing repainting the panel the pixels would keep the first value until the popup expired. Only the arbitration's
# *immediate-commit* arm needs its own repaint -- the throttled arm (a turn inside `kMinUpdateIntervalMs`) arms
# `pending_flush_remaining_ms_`, which `next_timer()` reports and `timer_repaints()` resolves to `{.oled = true}`, so a
# FAST turn repaints itself. `ParamPopupScene::show` reports whether it committed, and
# `GuestKnobPresentation::show_value_popup` (which `ModKnobs::show_popup` calls) files `Action::Kind::Repaint` on
# `SurfaceRole::Main` when it did -- the `display->displayNotification(...)` in `View::displayModEncoderValuePopup`
# (`gui/views/view.cpp`) being a write AND a blit. Deleting that action turns this frame back into a copy of
# `popup_shown`.
0     snapshot idle              # the audio clip view, no popup -- `.state` has one `scene` line
150   encoder GoldUpper +1
200   snapshot popup_shown       # `ModKnobs` wrote the param and pushed the popup: the MASTER LEVEL
                                 # name/value notification strip over the top of the clip view, and
                                 # a second `scene` line in `.state`
300   encoder GoldUpper +25
400   snapshot popup_moved       # twenty-five more detents on the SAME param: the strip's value
                                 # moves and the knob's indicator ring with it. Nothing is pushed a
                                 # second time (`show_popup`'s already-stacked guard,
                                 # `ModKnobs::show_popup`), so `.state` still has exactly two
                                 # `scene` lines -- what changed is the text and the ring
# +2100 ms of quiet ticks, no input at all. `kPopupLifetimeMs` is 2000 ms from the last commit
# (`param_popup_scene.cpp`), so the deadline falls at ~2300.
2500  snapshot popup_expired     # the popup ran its own timer down and removed ITSELF --
                                 # `after_render`'s `Action::Kind::Remove`, never `Pop`
                                 # (`ParamPopupScene::after_render`). The clip view owns the panel again
                                 # and `.state` is back to one `scene` line, with the indicator
                                 # ring left where the 300 ms turn put it
2600  quit
