# Level-2 acceptance (E4 task 13): `overlay::ParamPopupScene` (E4 task 1), pushed by
# `services::ModKnobs` (E4 task 2).
#
# **How the scene gets on the stack: nothing in this script pushes it.** A gold-knob turn is offered
# to the top scene first (`shell/router.h`'s `route()`, which is legacy's `UI::modEncoderAction` ->
# `view` fallback), `AudioClipScene` declines it explicitly ("the two gold knobs and the tempo
# encoder are `services::ModKnobs`'s", `audio_clip_scene.cpp:247-251`), and
# `ModKnobs::mod_encoder_action` then writes the param and calls `show_popup`, whose last statement
# is `stack_.push(SceneId{kParamPopupSceneKind})` (`services/mod_knobs.cpp:399`). **This script
# cannot exist with `Services{}`**: with a null mod-knob service the turn is dropped and no popup
# frame is ever produced. It is the one script here whose whole subject is a service.
#
# The base scene is `AudioClipScene` on the same clip the knobs are pointed at, so the popup is
# composited over something rather than over a blank panel -- `ParamPopupScene::oled_transparent`
# reports true for `SurfaceRole::Main` precisely so the scene beneath shows around it.
#
# **The turn at 100 ms is SWALLOWED, and that is the port working, not the script failing.**
# `ModKnobs::set_target_with_timeline` opens with `pretend_knobs_untouched()`
# (`services/mod_knobs.cpp:120`, legacy's `View::pretendModKnobsUntouchedForAWhile`,
# `view.cpp:1951-1955`), which backdates `InputLowering::last_turn_ms_` by a second -- so the next
# gold turn is not "recent" and `InputLowering::action_gold_turn` writes it off as the opening half
# of a possible wiggle (`input_lowering.cpp:206-231`). Every gold gesture on the device therefore
# costs a detent to arm, and the fixture sets the mod target before the run exactly as
# `View::setActiveModControllableTimelineCounter` does on the device. Found by recording the frame
# and looking at it: the first version of this script turned once and recorded a `popup_shown`
# golden byte-identical to `idle`.
#
# (`menu_scripts_spec.cpp`'s header records the *other* half of this: with no target ever set,
# `last_turn_ms_` stays 0 and a script's clock starts at 0, so a turn before t=500 is spuriously
# inside the window. Both arms are artefacts of where the clock starts; this one is the arm the
# device is always in, because something always sets the mod target first.)
#
# **THE TURN AT 300 ms HAS NO SNAPSHOT AFTER IT, AND THAT IS A DEFECT, NOT AN OMISSION.** See the
# `it` block in `sim/scenes_spec/scene_scripts_spec.cpp`, which asserts in C++ what the pixels cannot
# show: the turn moves the popup's own text (`shown_value()` goes from "26" to "45") and moves the
# knob indicator, but **nothing repaints the OLED**, so the panel keeps showing "26" until the popup
# expires. `ModKnobs::mod_encoder_action` files a `RepaintAll` only for `note_tails_changed`
# (`services/mod_knobs.cpp:306-314`) and nothing at all for a popup whose value changed; the popup's
# own `next_timer()` is its full 2000 ms lifetime, so the next OLED frame is the one that draws its
# disappearance. The first turn is visible only because *pushing* the scene arms the gate. Recording
# a `popup_moved` golden here would have frozen that bug into a picture, so there is no such frame.
0     snapshot idle              # the audio clip view, no popup -- `.state` has one `scene` line
100   encoder GoldUpper +1       # armed, not acted on: see above
150   encoder GoldUpper +1
200   snapshot popup_shown       # `ModKnobs` wrote the param and pushed the popup: the MASTER LEVEL
                                 # name/value notification strip over the top of the clip view, and
                                 # a second `scene` line in `.state`
300   encoder GoldUpper +25      # deliberately unsnapshotted -- see the defect note above. The
                                 # `indicator upper` line of `popup_expired` is where this turn IS
                                 # visible: it is the one surface that did repaint
# +2200 ms of quiet ticks, no input at all. `kPopupLifetimeMs` is 2000 ms from the last show
# (`param_popup_scene.cpp:37`), so the deadline falls at ~2300.
2500  snapshot popup_expired     # the popup ran its own timer down and removed ITSELF --
                                 # `after_render`'s `Action::Kind::Remove`, never `Pop`
                                 # (`param_popup_scene.cpp:368`). The clip view owns the panel again
                                 # and `.state` is back to one `scene` line, with the indicator
                                 # ring left where the 300 ms turn put it
2600  quit
