# **This script runs with `Services{}` -- three `NullService`s -- and so does every other menu
# script here.** That is deliberate (the ruling is in E4's ledger: three plans' goldens were recorded
# against null services, and re-recording them as a side effect of building the services would be a
# diff nobody could review), but it means these goldens describe a shell with no mod-knob service in
# it, and spec F will install one.
#
# **This file used to say the answer for THIS script was measured, and was "nothing moves".** The
# `300 encoder GoldUpper +2` step below is claimed by `MenuScene`'s own `int_value` widget during
# render, so `Router::route_post_render` drops the event before `Router::run_chain` is entered
# (`src/shell/README.md`) and `services::ModKnobs` never sees it -- and the conclusion drawn from
# that, that installing the services would leave this script alone, is **false**.
#
# F1 task 11 installed the real three over this block and measured it: the spec's own assertion that
# `+2` detents on `nodes::saturation` reads back 4 **fails, reading 0**, and
# `after_gold_turn.oled0.pbm` moves with it (the leaf draws 0 instead of 4). No `ParamPopupScene` is
# pushed -- that half of the old claim survives -- so the turn is still not going through the chain.
#
# **The turn is swallowed by the gold-knob wiggle debounce, and a service is what armed it.**
# `InputLowering::action_gold_turn` runs on the gold path unconditionally, gated on no service --
# the Continuous arm of `InputLowering::apply_encoder_edges` (`shell/input_lowering.cpp:191`),
# which `on_encoder_edges` forwards to (`:158-163`). It swallows a turn unless
# `(now_ms - last_turn_ms_[role]) < short_press_ms` (`:214`, 500 ms, `shell/input_lowering.h:26`).
# `ModKnobs::pretend_knobs_untouched()` (`scenes/services/mod_knobs.cpp:193-197`) writes that same
# array through `InputLowering::pretend_knob_untouched` (`input_lowering.cpp:451-461`,
# `last_turn_ms_ = now_ms - 1000`), and the fixture reaches it twice at construction --
# `set_target_with_timeline` (`mod_knobs.cpp:120`) and `set_mod_region` (`:165`) -- **but only with a
# `mod_target` seeded**. So for the `300 encoder GoldUpper +2` step below:
#
#   Services{} or an unseeded ModKnobs:  300 - 0        =  300 <  500  -> acted    -> 4
#   real three with a seeded mod_target: 300 - (0-1000) = 1300 >= 500  -> swallowed -> 0
#
# E4's final review added `tests/ui-scripts/shell/menu_gold_turn.txt`, which drives this same node
# with the real three installed and DOES record the value moving to 4. The difference is one step:
# that script turns `+1` at t=100 first, setting `last_turn_ms_` to 100, so its `+2` at t=150 sees
# `50 < 500` and acts. **Arming the debounce the same way here is the owed fix**, and it has to come
# before the re-record -- otherwise the new goldens depict a first-turn-swallowed gesture and this
# script stops recording the edit it exists for. See `sim/scenes_spec/menu_scripts_spec.cpp`'s
# header for the full measurement and the residual (two indicator lines plus `led Mod1 on`).
#
# **It is not the answer for every menu script.** Where a page reads no edit encoder -- `menu_decimal`'s
# first `GoldUpper` turn is the worked example, and its snapshot was dropped in E3 task 10 for being
# byte-identical to the frame before it -- the turn is unclaimed, falls through the whole chain and
# is dropped today. With a real `ModKnobs` it will write the mod param and push a popup over the
# menu. Those goldens are owed a re-record when the services are installed; `src/scenes/README.md`'s
# carry table and migration section 10.2 both carry the row.
#
