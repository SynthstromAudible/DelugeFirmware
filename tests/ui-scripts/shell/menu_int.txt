# F1 task 11 installed the real three over this block WITH a seeded target and measured it: the

# **The turn is swallowed by the gold-knob wiggle debounce, and seeding a target is what armed it.**
# `InputLowering::action_gold_turn` runs on the gold path unconditionally, gated on no service --
# the Continuous arm of `InputLowering::apply_encoder_edges` (`shell/input_lowering.cpp:191`),
# which `on_encoder_edges` forwards to (`:158-163`). It swallows a turn unless
# `(now_ms - last_turn_ms_[role]) < short_press_ms` (`:214`, 500 ms, `shell/input_lowering.h:26`).
# `ModKnobs::pretend_knobs_untouched()` (`scenes/services/mod_knobs.cpp:193-197`) writes that same
# array through `InputLowering::pretend_knob_untouched` (`input_lowering.cpp:451-461`,
# `last_turn_ms_ = now_ms - 1000`), and the fixture reaches it twice at construction --
# `set_target_with_timeline` (`mod_knobs.cpp:120`) and `set_mod_region` (`:165`) -- **but only with a
# `mod_target` seeded**, which is why the fixture here leaves it null. So for the `300 encoder
# GoldUpper +2` step below:
#
#   Services{} or an unseeded ModKnobs:  300 - 0        =  300 <  500  -> acted    -> 4  <- what runs
#   real three with a seeded mod_target: 300 - (0-1000) = 1300 >= 500  -> swallowed -> 0
#
# E4's final review added `tests/ui-scripts/shell/menu_gold_turn.txt`, which drives this same node
# with the real three installed and DOES record the value moving to 4. The difference is one step:
# that script turns `+1` at t=100 first, setting `last_turn_ms_` to 100, so its `+2` at t=150 sees
# `50 < 500` and acts. **Arming the debounce the same way here is the owed fix**, and it has to come
# with the seeding -- otherwise the seeded goldens depict a first-turn-swallowed gesture and this
# script stops recording the edit it exists for. See `sim/scenes_spec/menu_scripts_spec.cpp`'s
# header for the full measurement and the residual (two indicator lines plus `led Mod1 on`).
