# Level-2 acceptance (task-11 brief): a real shift+pad shortcut jump (pad (8,7) of
# paramShortcutsForSounds, &lpfFreqMenu) from the sound root, then the generic recipe on the
# landed-on node.
0     snapshot idle
50    button Shift down
100   pad 8 7 down 64
120   pad 8 7 up
130   button Shift up
140   snapshot after_shortcut
200   encoder Select +1
# E3 task 10: `lpf_freq` renders through `render_leaf_decimal`, which claims-and-ignores the select
# encoder for the same reason `render_leaf_int` does (menu_int.txt's own note) -- so this snapshot
# was byte-identical to `after_shortcut`. The step stays; the snapshot does not.
300   button SelectEnc down
320   button SelectEnc up
340   snapshot after_select_press
400   encoder GoldUpper +2
# E2 task 9: the GoldUpper turn above lands on the page the select press opened, which reads no
# edit encoder -- so it inks nothing new and its snapshot was byte-identical to `after_select_press`.
# The step stays (the spec asserts the value did NOT move here) and the snapshot does not: a golden
# that records nothing is a golden that can never fail for the right reason.
500   button Back down
520   button Back up
540   snapshot after_back
# E2 task 9: the select press above no longer ascends -- `source0_transpose` / `lpf_freq` are
# `PatchedParam` nodes, whose `selectButtonPress` opens the source picker
# (`gui/menu_item/patched_param.cpp:32-38`), so the GoldUpper turn at that point lands on the
# picker and edits nothing. The Back above comes back to the leaf; this second GoldUpper turn is
# what edits it, and keeps this script's "the value moved" assertion about the leaf's own kind.
600   encoder GoldUpper +2
620   snapshot after_back_gold
700   quit
