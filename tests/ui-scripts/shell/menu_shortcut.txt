# Level-2 acceptance: a real shift+pad shortcut jump (pad (8,7) of
# paramShortcutsForSounds, &lpfFreqMenu) from the sound root, then the generic recipe on the
# landed-on node.
#
# `int_value` edits with the select turn (`ui/oled/values.cpp`'s `select_delta`), never the gold
# pair, so the first select turn (`200`, below) edits `nodes::lpf_freq` too, which
# `after_select_press`'s golden shows.
0     snapshot idle
50    button Shift down
100   pad 8 7 down 64
120   pad 8 7 up
130   button Shift up
140   snapshot after_shortcut
200   encoder Select +1               # 0 -> +1: edits
300   button SelectEnc down
320   button SelectEnc up
340   snapshot after_select_press
400   encoder GoldUpper +2
# `lpf_freq` is a `PatchedParam` node, so the select press above opened the source picker, not the
# leaf -- `enum_value` renders that page, and it has always read the select turn, never the gold
# knobs. So this `GoldUpper` lands on a page that reads no edit encoder at all: it inks nothing new,
# and a snapshot here would be byte-identical to `after_select_press`, so there is none.
500   button Back down
520   button Back up
540   snapshot after_back
# The select press above does not ascend -- `source0_transpose` / `lpf_freq` are `PatchedParam`
# nodes, whose `selectButtonPress` opens the source picker (`gui/menu_item/patched_param.cpp:32-38`).
# The Back above comes back to the leaf; the select turn below is what edits it a second time, and
# keeps this script's "the value moved" assertion about the leaf's own kind.
600   encoder Select +2               # +1 -> +3: `int_value` claims the select turn, not the
                                      # gold knobs
620   snapshot after_select_edit
700   quit
