# Synth golden masters

The regression net for the synth engine: every preset here is rendered on the Embassy host harness and its output
must match its record in `../presets.json`. The gate is `golden-synth` in `tests/registry.toml`, and its check module
is `tests/integration/checks/render_preset.py`.

## How a case renders

Each case is one run of golden_vt_render's `render_preset` scenario
(`tests/integration/scenarios/render_preset_scenario.h`):

- The card holds the preset at `SYNTHS/PRESET.XML`. The blank boot song replaces its built-in default synth with the
  first preset in `SYNTHS/`, through the real deserialization path, so a case needs no loading code of its own.
- A DIN note script plays it. Every case is bound to MIDI channel 1: the synthesized presets carry
  `inputMidiChannel="0"`, and for the imported ones the check module injects `<inputMidiChannel>0</inputMidiChannel>`
  into the copy it stages. The committed files stay as published.
- The render runs in real time on the audio tier, 128 frames a block, and the output is captured from the start of the
  note script. CPU direness must stay 0, so every case renders on its full-quality paths.

## Running

```sh
./dbt test golden-synth                                     # every case, against presets.json
RENDER_PRESET_FILTER=sine,fm ./dbt test golden-synth        # the cases whose name holds any of these
RENDER_PRESET_UPDATE=1 ./dbt test golden-synth              # record instead of comparing
```

A case takes a fraction of a second of wall time (the harness runs in virtual time), and the cases run in parallel.

## Recording

A changed record means the sound changed. When the change is meant, record it with `RENDER_PRESET_UPDATE=1` and
explain it in the commit, case by case. Never record a silent render: the check fails any render whose peak is below
16 in 16-bit terms, because silence almost always means the preset failed to load (the default synth that remains is
not bound to the note script's channel).

## The corpus

- `*.xml`: the synthesized cases, each aimed at one engine feature, generated by `make_corpus.py`. Edit it, re-run
  it and commit the changed XMLs; the committed XMLs are the source of truth.
- `factory/`: the sample-free synth presets from the Deluge OLED V4.1.0 factory card (168 of 171). They are in the
  old tag-based format, so they also exercise the legacy loader and the firmware-version compatibility transforms.
- `community/`: the sample-free presets from the Deluge Community Preset Pack 1.2 (128 of 171), in the attribute
  format, including DX7 presets with embedded patches.
- `sample/`: sample playback through the windowed-sinc interpolator, the linear fallback, reverse reading, the
  time-stretcher and mono samples. Their sources are `sample/_tone.wav` and `_tone_mono.wav`, generated by
  `make_sample.py`; each case's `<case>.wav` is a symlink to one of them.
- `wavetable/` and `wavetable_basic`: wavetable oscillators.

A case may carry, beside its preset:
- `<case>.notes`: its note script, instead of `default.notes`. One event per line, `<frame> <hex MIDI bytes>`, with
  `#` comments, and frames counted from the start of capture in nondecreasing order.
- `<case>.wav`, `<case>.2.wav`: staged as `SAMPLES/WT.WAV` and `SAMPLES/WT2.WAV`, the paths its preset names.

Captures are 2 s long. The exceptions, and the cases fed the harness's test input signal, are listed at the top of
the check module.

Not yet covered: DX7 cartridges, sidechain from audio, and the mod FX, delay and reverb, which the corpus presets
leave neutral for a future FX-chain corpus.
