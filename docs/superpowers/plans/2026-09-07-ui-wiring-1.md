# UI Wiring F1 — the shell as guest, behind a toggle

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the ported menu reachable on a real device for the first time — link `deluge_scenes` into
the firmware, let an application install the three services, and run a full `Shell` inside one legacy
`UI` (`ShellHostUI`) that the menu's fourteen entry points open when a runtime toggle is on.

**Architecture:** Spec F §2.1's *shell as guest*: `ShellHostUI : UI` is registered like any other legacy
UI and pushed with `openUI(&shellHostUI)`; inside it a `Shell` runs its own scene stack. Legacy's input
hooks forward into `InputLowering`, legacy's render hooks are served by a `SurfaceSet` that writes into
`OLED::main` and `PadLEDs::image`, and `timerCallback` drives `Shell::tick`. Nothing about the legacy
path changes: the guest is opened only when `RuntimeFeatureSettingType::ShellMenu` is on, so with the
toggle off the firmware behaves exactly as it does today.

**Tech Stack:** C++23 (`src/scenes/`, `src/shell/`, `src/ui/`, `src/gfx/`), the legacy C++ app
(`src/deluge/`), the Rust BSP's build glue (`src/bsp/rust/build.rs`), CMake, and spec G's three test
levels — unit specs, level-2 scene scripts, and the level-3 headless app.

**Spec:** `docs/superpowers/specs/2026-08-26-ui-migration-design.md` (spec F) — §2.1 is the topology,
§3 the shared framebuffers, §10.2 the nine blockers this plan closes five and a half of. Read
`docs/superpowers/specs/2026-08-26-ui-shell-design.md` §15 and
`docs/superpowers/specs/2026-08-26-ui-scenes-menus-design.md` §16 for the contracts E4 corrected.

**Branch:** `ui/wiring-1` off `ui/scenes-4`. Branch in place — no worktrees.

## Global Constraints

Every task's requirements implicitly include this section.

1. **No new UI, scenes or UX.** Kate, 2026-09-06: *"we shouldn't be adding any scenes/ui/ux that didn't
   exist prior."* This plan is the first that changes what a player sees, and the rule binds harder for
   it, not less: **with the toggle on, the guest must do what `SoundEditor` does** — not something
   better, tidier or more consistent. A difference you cannot trace to a legacy line is a defect to
   report. The toggle itself is new UI in the settings menu and is the one deliberate exception, because
   without it there is no way to ship this at all.
2. **With the toggle OFF, nothing may change.** Every existing test, golden and behaviour is the
   regression baseline. A task that moves a golden with the toggle off has broken something.
3. `snake_case` functions and variables, `PascalCase` types, `k`-prefixed constants in new
   `src/scenes/`, `src/shell/` and `src/ui/` code. **`ShellHostUI` lives in `src/deluge/gui/ui/` and is
   legacy-facing: it follows legacy's camelCase**, which is what a façade over legacy is for.
4. Layer rules, unchanged: `src/scenes/**` may include `scenes/`, `shell/`, `ui/`, `gfx/`, `notify/`,
   `libdeluge/`, the standard library, `model/`, `modulation/`, `playback/`, `processing/`, `storage/`,
   `gui/l10n/`, `definitions_cxx.hpp` — **never `gui/` otherwise, never `hid/`**. `src/shell/**` may
   never include `model/**`. `ShellHostUI` is in `gui/` and may include anything legacy may, which is
   exactly why the guest lives there and not in the libraries.
5. No heap in library code; no wall clock in `src/shell/**` or `src/ui/**` (`shell-no-clock`).
6. Never edit `src/bsp/rza1` (retired). Never commit `src/bsp/rust/Cargo.lock`.
7. Cite legacy by **symbol AND line**, and verify every line number with numbered output (`grep -n`) —
   never by counting lines in output that does not carry them. That method error put a wrong citation in
   E4's own ledger.
8. All four checkers exit 0, including `check_citations.py --strict` (a blocking CI gate that
   brace-matches each cited symbol's real body extent) and `check_layer_rules.py --audit-symbols`. The
   layer-rule baseline **may only shrink**.

  the start of this plan.

- `./dbt build Debug` — **stops at a known pre-existing `ld.lld: … Invalid record`** from a Rust/LLVM

  **Task 1 changes what is in that link, so from Task 1 on, check the failure is still that one.**
- **From Task 9 on**, the level-3 app scripts: `ctest --test-dir build-sim -R ui_app_scripts`. These are
  excluded from the usual CI gate (`-E ui_app_scripts`) because they are slow; this plan is the reason
  they exist, so run them.

### Why this plan carries interfaces and citations, not bodies

The fourth plan in a row to do it. E2's plan carried illustrative code and **every one of its thirteen
tasks found an error in it**; the three plans since carried interfaces, contracts and exact citations,
and their implementers did better work faster. A signature, a file path and a verified legacy citation
are things a plan can get right; a body written from outside the implementer's context is a thing the
implementer must first debug and then discard.

**The corollary binds the implementer: the legacy citation in a step is the requirement, not the step's
prose.** Where the two disagree, read the code and report the plan's error. Every task in E4 found at
least one; four of them found a premise that was simply false.

### The oracle discipline, and what changes for this plan

Every prior plan compared the port against legacy at the level of *objects* — drive `SoundEditor`'s
methods and the port's side by side on one fixture. **This plan can do better, and must.** Spec G's
level 3 (`sim/CMakeLists.txt:655-700`) runs the whole application headless on a deterministic frame
clock under `DELUGE_HOST_DETERMINISTIC=1 DELUGE_HOST_SCRIPT=<file>`, writing `<name>.oled<N>.pbm` and
`<name>.state` and byte-comparing them against `tests/golden/ui/app/<name>`.

So the acceptance test for this plan is **the same script run twice — toggle off and toggle on — with
the two snapshot trees diffed against each other**. That is legacy `SoundEditor` against the ported
`MenuScene`, in the real firmware, on the real boot path. It is the comparison spec E §7 has described
since the beginning and that no plan has been able to run. Task 11 builds it.

The disciplines that got the port this far still apply and are not optional:

- **Each side driven from its own sentinel.** A comparison whose reference is computed from the port's
  own state proves nothing; that shape survived three plans here before a review caught it.
- **Mutation-prove every mapping**, in both directions, and name both mutations in the commit message.
  A mutation that passes is the finding.
- **Look at every golden.** One recorded from a blank surface passes forever. E4 shipped a pad
  comparison that passed 27/27 on two black grids, caught by someone rendering the picture.
- **Quiet-tick coverage** for anything time-driven, and **both panel geometries** for anything that draws.
- Where something genuinely cannot be driven, say so **at the spec site** and count it as uncovered.

## Task 4: `GuestSurfaceSet` — the shell's surfaces over legacy's buffers

**Files:**
- Create: `src/deluge/gui/ui/shell_guest_surfaces.{h,cpp}`
- Test: a new host spec under `tests/spec/` driving it against a fake legacy buffer pair

**Interfaces:**
- Produces: `class GuestSurfaceSet final : public deluge::ui::shell::SurfaceSet` implementing the six
  pure virtuals (`src/shell/surfaces.h:153`+): `oled_busy(uint8_t)`, `blit(uint8_t, std::span<const uint8_t>, uint16_t, uint16_t)`,
  `pad_output_space()`, `send_columns(uint8_t, const ColumnPair&)`, `set_led(uint8_t, bool)`,
  `set_indicator(uint8_t, const KnobIndicator&)`.
- Consumes: `OLED::main` (`hid/display/oled.h:88`), `PadLEDs::image` (`hid/led/pad_leds.h:33`).

**The question this task must settle with evidence, not assumption.** Spec F §3 says the formats are
byte-identical so "aliasing is free and copy-less": the guest's `Main` surface *is* `OLED::main`'s
storage, and the grid surface's rows alias `PadLEDs::image` via `PadGrid::row(y)`. But
`SurfaceSet::build` (`src/shell/surfaces.cpp:15-40`) emplaces **its own** canvas storage
(`storage_[i]`) and its own `grid_storage`. So either the shell needs a seam for borrowed storage, or
the guest copies.

- [ ] **Step 1: Read `SurfaceSet::build` and decide, with the sizes measured.** If you add a seam, it is
      a shell change and belongs in the shell spec's §15. If you copy, **measure the copy** — panel bytes
      per blit and grid bytes per flush, at the real tick rate — and put the number in the report and at
      the code. "A copy is probably fine" is not an answer this stack accepts; E3 shipped two blit
      regressions that a number would have caught.
- [ ] **Step 2: Write the failing spec** against a fake buffer pair: what the shell writes appears in the
      legacy buffers, and `blit` marks the panel changed rather than pushing bytes anywhere.
- [ ] **Step 3: Implement the six hooks.** `blit` → `OLED::markChanged()`; `send_columns` →
      `sendOutMainPadColours()`'s path; `set_led`/`set_indicator` → `indicator_leds`. Cite the legacy
      function each one replaces.
- [ ] **Step 4: `oled_busy` and `pad_output_space` are back-pressure questions** legacy answers its own
      way. Find what legacy actually consults and forward to it; do not invent a policy.
- [ ] **Step 5: Mutation-prove** that a write through the shell reaches the legacy buffer — perturb one
      pixel's path and watch the spec fail.
- [ ] **Step 6: Run the gates and commit.**
