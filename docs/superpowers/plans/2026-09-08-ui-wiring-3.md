# UI Wiring 3 — the choice dispatcher Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give `BrowserScene::take_choice()`'s outbox a consumer, so a sample chosen in the ported
browser is actually loaded — and lands the user on the source page, as legacy does.

**Architecture:** F1 made the ported scene stack run inside the firmware as a guest UI behind a
runtime toggle; F2 gave `MenuScene::take_action()`'s verb mailbox a consumer drained from the guest's
tick. This plan does the same for the *noun* half of the same wall: `BrowserScene`'s `Sample`
descriptor answers `AcceptOutcome::Defer`, parks the chosen path, and closes, because
`SampleBrowser::claimCurrentFile` reaches five `gui/` and `hid/` symbols the scenes layer may not
name. The dispatcher performs the load against the legacy object and then re-roots the menu.

**Tech Stack:** C++20, CppSpec (`sim/scenes_spec`, `tests/spec`), CMake + ninja, the level-2 shell
script harness and the level-3 application A/B.

**Spec:** `docs/superpowers/specs/2026-08-26-ui-migration-design.md` — §10.2 **item 4**, the last
open dispatcher. The seam's own contract is `src/scenes/browser/browser_scene.h:196-232`
(`Descriptor::accept`), which is unusually complete and should be read before the spec.

**Scope decision (Kate, 2026-09-08):** drain + `claimCurrentFile` + the re-rooting. **Deferred:**
`osc::AudioRecorder`'s identical heading pair, and gating legacy entry **site 10**.

## Global Constraints

1. **No new UI/UX.** Everything must be a port of something legacy already does. A comment saying
   "legacy has none" or "spec design, not a port" is a defect to **report**, not a decision already
   made. `src/shell/shell.cpp`'s `dim_grid` is deliberately left standing and marked OUTSTANDING —
   Kate deferred it. Do not remove it, do not treat it as decided.
2. **With the toggle OFF, nothing may change.** `shellMenuEnabled()` is
   `RuntimeFeatureSettingType::ShellMenu`, default Off. F2 accepted **two** arguments for
   unconditional code and you must pick the one that fits and say why: *reachability* (F2 task 6 —
   nothing new runs with the toggle off) and *what is written* (F2 task 5 — a gate would itself be
   the bug, because the toggle is runtime-flippable). **`claimCurrentFile` has real side effects**,
   so reachability is almost certainly your argument; prove it rather than inherit it.
3. `snake_case` / `PascalCase` / `k` constants under `src/scenes/` and `src/shell/`. The scenes
   library never includes `gui/` (except `gui/l10n/`) or `hid/` and never calls frame primitives.
   `src/shell/**` never includes `model/**`. No `Action::Kind::LockInput`.
4. Never edit `src/bsp/rza1` (retired). Never commit `src/bsp/rust/Cargo.lock`.
5. Cite legacy by **symbol AND line**, verifying every line with numbered output (`grep -n`). A
   citation carrying only a line number cannot survive a shift and no tool can catch it.

### The hazard that shapes every spec in this plan

**`storage::Owner::run` is inline on the host** (`storage/owner.h:55-59`), and
`SampleBrowser::claimCurrentFile` is dispatched onto that owner. F2 task 3 hit the same wall with
`StemExport` and its answer is the precedent: **declare the decision function separately and drive
that**, so no example ever reaches the real side effect. Here the side effect is a sample load off
`DELUGE_SD_ROOT` — it will read the card, allocate, and touch `AudioEngine`. Design for that in
Task 1, not in Task 4 when a spec hangs.

### What F1 and F2 learned that binds this plan

- **The citation sweep failed six ways across those two plans**, and each fix closed one stage and
  exposed the next: (1) hand-written path list, (2) suffix list — `.py`, later `.md`, (3) match
  anchoring (basename collision), (4) per-endpoint arithmetic, (5) same-commit-authored citations
  with no BASE text — `check_citation_shift.py`'s own **limitation 4**, walked into by a task that
  had read it, (6) a range's *end* being unchecked, since `certainly_wrong` clamps `end` to `start`.
  Modes 1-3 are about *finding* citations; 4 is about being right once found; 5 and 6 are about
  citations nothing compares at all. **Task 6 of F2 published `verify.py`** for mode 4; nothing
  handles 5 or 6 except reading the sentence.
- **The wrong-population error fired eight times**, and its durable answer is: **stop hand-writing
  the population — derive it from the thing that already knows it** (`git ls-files`), and **publish
  the recipe, never the number**.
- **"A claim broader than its mechanism"** was the most frequent review finding in both plans.
- **Report a mutation that passes**, with the reason. Every F2 task did, and in every case the review
  made the finding *stronger* than the report had it.
- **Five times a task's own tooling undid work it had already got right.** Probe files with nothing
  uncommitted in them; scope formatting commands to the languages they format; and check what a
  harness's exit code actually measures — one F2 harness read `tail`'s status and reported five
  killed mutations as survived.

## What is already true, and what is actually missing

Read this before Task 1; it is the difference between this plan and legacy's version of the same job.

Legacy's re-rooting exists because `claimCurrentFile` **tears `soundEditor` down and rebuilds it**
(`gui/ui/browser/sample_browser.cpp:1075-1086`: `closeUI(&soundEditor)`, `focusChild`,
`menuItemNavigationRecord[0] = parentMenuHeadingTo`, `navigationDepth = 0`, `openUI(&soundEditor)`).
The headings `menuItemHeadingTo` / `parentMenuHeadingTo` are written on the way *in* by
`SoundEditor::maybeGetParentMenu` (`gui/ui/sound_editor.cpp:2073`, file-selector arm `:2034-2039`)
precisely so the rebuild knows where to land.

**The port never lost the menu.** `nodes::FileBrowserItem::on_focus` (`scenes/menu/nodes/sample.cpp`)
pushes the browser as a *scene* over the menu, and that file's own note says it exactly:

> `MenuState::path`/`depth` already are that record and `go_up_on_resume` already steps out of the
> item, so what is actually missing is the **re-rooting**.

So this plan does **not** need a port of `maybeGetParentMenu`'s heading pair. It needs one thing:
after a successful claim, land the menu on the **source page with the file selector focused**, rather
than wherever `go_up_on_resume` leaves it. **Task 3 owns deciding what that target is** — and it is a
decision, not a transcription, because legacy's answer is spelled in `MenuItem*`s that have no port.

## Task 1: The drain, and the claim that must not run in a spec

**Files:**
- Create: `src/deluge/gui/ui/shell_choice_dispatch.{h,cpp}`, `sim/scenes_spec/browser_choice_spec.cpp`
- Modify: `src/deluge/gui/ui/shell_host_ui.cpp`, `scripts/check_layer_rules.py`

**Interfaces:**
- Produces: `namespace deluge::gui::ui { void dispatchShellChoices(); }` — drains
  `browser::browser_scene().take_choice()` once and performs it.
- Consumes: `BrowserScene::take_choice()` (`src/scenes/browser/browser_scene.h:371`), returning
  `std::optional<BrowserChoice>`; `BrowserChoice` is `{BrowserId id; std::string path;}` (`:248`).

- [ ] **Step 1: Read the contract before the code** — `browser_scene.h:196-232`'s
      `Descriptor::accept`, and `browser_scene.cpp`'s `Defer` arm (`:210`, applied at `:888`).
      Re-resolve every line; F2 found six of nine controller briefs carried a stale citation.

- [ ] **Step 2: Decide where the claim's side effect lives, and make it drivable.**
      `claimCurrentFile` runs inline on the host through `storage::Owner::run` (`storage/owner.h:55-59`).
      Follow F2 task 3's precedent: a separately declared function the spec can drive, with the real
      call behind it. **Write down what a spec would do if it reached the real one** — read the card,
      allocate, touch `AudioEngine` — so the next reader knows why the seam exists.

- [ ] **Step 3: Write the failing spec.** The load-bearing example is that the drain runs on a tick
      where **the browser has already closed itself** — `Defer` parks *and closes*, so by drain time
      the scene is off the stack. An example that drains while the browser is still open tests a
      state that never happens.

- [ ] **Step 4: Implement the drain**, called from `ShellHostUI::timerCallback` beside
      `dispatchShellActions()`. **Order matters and you must state it**: both drains run after
      `Shell::tick`; say whether a choice and an action can be pending in the same tick, and what
      happens if so.

- [ ] **Step 5: Mind F2's stray-timer guard.** `rearmTimer` skips when `getCurrentUI() != this`
      (F2's final fix). If your claim opens or closes a UI, you inherit that interaction — check it
      and say what you found.

- [ ] **Step 6: Prove the drain, both directions.** Delete the call and confirm the example reddens
      for the reason it names; then mutate the dispatcher body to stop reading `take_choice()` and
      confirm a *different* example reddens. F2 task 1 needed both to separate call site from body.

- [ ] **Step 7: Run every gate. Commit.**

## Task 3: The re-rooting — a `MenuScene` entry point, and deciding the target

**Files:** Modify `src/scenes/menu/menu_scene.{h,cpp}`, `src/deluge/gui/ui/shell_choice_dispatch.cpp`, specs

**This is the task §10.2 item 4 is actually about.** Everything before it is plumbing the F2 pattern
already established.

- [ ] **Step 1: Establish what legacy lands on.** `sample_browser.cpp:1075-1086`:
      `parentMenuHeadingTo->focusChild(menuItemHeadingTo)`, `menuItemNavigationRecord[0] =
      parentMenuHeadingTo`, `navigationDepth = 0`. The pair is written by
      `SoundEditor::maybeGetParentMenu` (`gui/ui/sound_editor.cpp:2073`, file-selector arm
      `:2034-2039`). **Read both and say, in nodes, what page that is** — the port's equivalent of
      "the oscillator's horizontal page with the file selector focused".

- [ ] **Step 2: Decide the target, and record it as a decision.** `nodes::FileBrowserItem`
      deliberately does not port the heading pair (`scenes/menu/nodes/sample.cpp`), so there is no
      stored answer to read back. Either the dispatcher derives the page from the `MenuContext` the
      browser was opened over, or `BrowserChoice` grows a field, or `MenuScene` remembers. **Pick
      one, say why, and say what the other two would have cost.**

- [ ] **Step 3: Add the entry point.** `MenuState::path`/`depth` may only be written by `MenuScene`
      (`menu_scene.h`'s mailbox contract — an item writing the menu's own navigation state is what it
      exists to prevent). F2 task 6 hit the same wall for the verb half and added
      `MenuScene::request_action` through the `menu_scene()` singleton, precedented by
      `nodes/context_menu_items.cpp:76`. **Follow that shape unless you can argue better**, and note
      that a new public mutator on a shipping class is what F2 task 1's ruling declined *for a test* —
      for production it is a different question, and it needs arguing.

- [ ] **Step 4: Write the failing spec.** Accept a file, then assert the menu's **path and depth**,
      not merely that something changed. Assert the *focused child* too — landing on the right page
      with the wrong item focused is the failure mode legacy's `focusChild` exists to prevent.

- [ ] **Step 5: Mutate the target.** Re-root one level too shallow and confirm the example reddens
      on the depth assertion; focus the wrong child and confirm it reddens on that one. Two
      mutations, two distinct kills — an example that catches both with one assertion is asserting
      too little.

- [ ] **Step 6: Retire the "one extra BACK press" cost** wherever it is recorded — at least
      `browser_scene.h:211-232` and `scenes/menu/nodes/sample.cpp`. **Find them by content**, not by
      the line numbers here; three handoff lists in F2 went stale before they were acted on.

- [ ] **Step 7: Run every gate. Commit.**
